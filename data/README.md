# Data Directory — Local Study Inputs

No study or example data are tracked in this repository. Copy the required files into this directory before running the workflow. The repository `.gitignore` excludes everything under `data/` except this README, so these local inputs are not added to future commits.

------------------------------------------------------------------------

## Source

The ASV inputs and taxonomy table are generated by the companion **DADA2 workflow**. Copy them into this directory under the filenames listed below and create a metadata file for the study.

------------------------------------------------------------------------

## Required Files (Not Included)

| Filename here | Source file in a companion DADA2 workflow | Description |
|----|----|----|
| `asv_count_table.csv` | `results/5_dada2_pipeline/asv_count_table.csv` | Sample x ASV read-count matrix |
| `asv_sequences.csv` | `results/5_dada2_pipeline/asv_sequences.csv` | ASV ID-to-sequence mapping |
| `asv_taxonomy.csv` | `results/5_dada2_pipeline/silva_taxonomy_table.csv` or `gtdb_taxonomy_table.csv` | DADA2-compatible taxonomy used by Step 5 to add informative labels while retaining ASV IDs |
| `metadata.tsv` | Study metadata prepared by the user | Sample condition and reference-group information used by Steps 3–5 |

------------------------------------------------------------------------

## File Formats

### `asv_count_table.csv`

- **Rows**: one per sample
- **Columns**: first column is the sample identifier; remaining columns are ASV IDs (`ASV1`, `ASV2`, ...) containing integer read counts

### `asv_sequences.csv`

- **Columns**: `ASV_ID`, `sequence`
- One row per ASV, with the ASV's nucleotide sequence (IUPAC codes only)

### `asv_taxonomy.csv`

Copy one taxonomy table from the companion DADA2 workflow into this directory and rename it `asv_taxonomy.csv`. [Step 5](../R/notebooks/5_taxon_contribution.md) reads this file to place the configured taxonomic rank beside each retained ASV identifier.

- The first column must be `ASV_ID` and match the identifiers in `asv_count_table.csv`.
- Standard rank columns are `Kingdom`, `Phylum`, `Class`, `Order`, `Family`, `Genus`, and `Species`.
- `Corrected_Species` and `Unique_Tax` from the DADA2 export may be retained.
- [Step 5](../R/notebooks/5_taxon_contribution.md) uses the rank selected by `tax_level` (default: `Genus`), appends the ASV ID so contributors remain distinguishable, and falls back to the raw ASV ID when a taxonomy value is missing.
- Additional provenance columns, such as `Taxonomy_Source`, may be retained.

------------------------------------------------------------------------

## Consistency Requirements

- Every ASV ID appearing as a column in `asv_count_table.csv` **must** have a matching row in `asv_sequences.csv`. [Step 1](../R/notebooks/1_prepare_picrust2_inputs.md) validates this and will stop with an error if any ASV is missing a sequence.
- ASV IDs are matched exactly (case-sensitive, no surrounding whitespace).
- Taxonomy rows may be absent for some ASVs; Step 5 retains their raw ASV IDs rather than silently dropping them.

------------------------------------------------------------------------

## What Happens Next

[Step 1](../R/notebooks/1_prepare_picrust2_inputs.md) of this workflow reads both files from this directory and writes the [BIOM](http://biom-format.org/)-format feature table and FASTA representative-sequence file that [PICRUSt2](https://github.com/picrust/picrust2/wiki) requires, into [results/1_prepare_picrust2_inputs/](../results/1_prepare_picrust2_inputs/).

------------------------------------------------------------------------

## Sample Metadata (`metadata.tsv`)

Required starting from [**Step 3**](../R/notebooks/3_nsti_quality_assessment.md) onward — the remaining notebooks join PICRUSt2's per-sample output against this file to determine condition membership and the reference condition. It is not needed for [Step 1](../R/notebooks/1_prepare_picrust2_inputs.md) or [Step 2](../R/notebooks/2_picrust2_pipeline.md). Notebooks that use it:

- [Step 3](../R/notebooks/3_nsti_quality_assessment.md) — NSTI quality assessment.
- [Step 4](../R/notebooks/4_functional_differential_abundance_analysis.md) — community-level MetaCyc and KEGG pathway differential-abundance analysis.
- [Step 5](../R/notebooks/5_taxon_contribution.md) — contribution analysis for selected MetaCyc and KEGG pathway predictions using contributing ASVs and taxonomy labels.

Create `data/metadata.tsv` as a tab-separated file with one row per sample and the following header and columns:

| Column | Required? | Description |
|----|----|----|
| `SampleID` | Yes | Must exactly match (case-sensitive, no surrounding whitespace) the sample identifiers used as column names in `asv_count_table.csv` / the BIOM table produced from it. |
| `Condition` | Yes | Experimental or clinical condition used for NSTI visualization, differential-abundance comparisons, and contribution summaries. Values are treated as unordered categories. |
| `Reference` | Yes | Use `TRUE` for every sample in exactly one reference/baseline `Condition` and `FALSE` for every sample in all other conditions. Step 4 compares each non-reference condition independently against this condition. |

### Consistency Requirements

- Every `SampleID` must exactly match a sample identifier present in the PICRUSt2 output being analyzed. Notebooks validate this and will stop with an error listing any mismatched sample IDs rather than silently dropping or misaligning samples.
- Every `SampleID` must be unique and every `Condition` value must be non-empty.
- Use concise, consistent `Condition` labels because they are reused in plot labels and exported summaries.
- Every row within a condition must have the same `Reference` value, and exactly one complete condition must be marked `Reference = TRUE`.
